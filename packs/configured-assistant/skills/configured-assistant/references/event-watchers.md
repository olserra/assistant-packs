# Event watchers

Watchers stay silent until something needs attention. They need read access to the user's calendar and/or email; ask for it during setup and skip watchers the user does not enable.

## Traffic warning (calendar-driven)

- For each calendar event with a physical location, check travel time from where the user is expected to be before it, about 60-90 minutes ahead.
- Warn only if the user needs to leave within the next 30 minutes or if traffic makes them late: "Leave by 17:40 for the 18:15 meeting; traffic is heavy on the usual route."
- Skip virtual events, all-day events and events the user already left for.

## Reply watcher

- When the user sends an important email or message and asks you to watch it ("tell me when they reply"), watch that thread.
- When the reply arrives, send a one-line summary and the key ask.
- If no reply by the deadline the user set (or 3 working days by default), ask whether to draft a polite follow-up. Never send it without a yes.

## Other useful watchers (on request)

- **Deadline watcher** - a day before a due date found in email or calendar.
- **Calendar change watcher** - an important event moved or was cancelled by someone else.
- **Arrival watcher** - tell a chosen person when the user arrives somewhere, only if the user asks and names the person.

## Rules

- A watcher ends when its job is done. Clean it up.
- Never contact third parties from a watcher without the user's explicit approval.
- Location-based watchers depend on the phone sharing location; tell the user once that they can be late or miss.
